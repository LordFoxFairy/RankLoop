# 自定义与自动化配置

## 站点自定义（不需要改代码）

编辑仓库根目录的 `rankloop.config.json`：

```json
{
  "siteName": "站点名称",
  "siteUrl": "https://你的域名",
  "lang": "zh-CN",
  "nav": [
    { "label": "首页", "href": "/" },
    { "label": "文档", "href": "/docs" },
    { "label": "GitHub", "href": "https://github.com/..." }
  ],
  "home": {
    "title": "首页大标题",
    "subtitle": "副标题说明文字",
    "actions": [
      { "label": "开始使用", "href": "/start", "primary": true },
      { "label": "了解更多", "href": "/docs" }
    ]
  },
  "theme": {
    "accent": "#0b62d0",
    "fontFamily": "system-ui, sans-serif",
    "contentWidth": "820px",
    "colorScheme": "auto"
  },
  "footer": "自定义页脚，支持 <a href=\"/x\">链接</a>",
  "headExtra": "<script defer src=\"统计脚本\"></script>"
}
```

| 字段 | 作用 |
| --- | --- |
| `nav` | 顶部导航；`/` 开头的链接自动适配子路径部署 |
| `home` | 首页 hero 区。配置后正文 H1 自动降级为 H2，保证全页只有一个 H1 |
| `theme.accent` | 主色，用于链接与按钮 |
| `theme.contentWidth` | 正文最大宽度 |
| `theme.colorScheme` | `auto` 跟随系统 / `light` / `dark` |
| `headExtra` | 注入 head 的自定义标签，用于统计代码等 |

`siteUrl` 与 `siteName` 可被环境变量 `SITE_URL` / `SITE_NAME` 覆盖，
便于同一份内容部署到不同域名（预览环境、正式环境）。

本地预览：

```bash
npm run site
cd dist-site && python3 -m http.server 4173
```

## 为什么不用 Astro / Next.js

本项目的核心价值是 **SEO 规则引擎与发布门槛**，渲染只需输出语义正确的 HTML。
引入渲染框架会带来：数百个依赖、独立构建步骤、框架版本升级维护，
与「零依赖、一键部署」的目标冲突。

配置外置后，改配色、导航、首页布局都不需要碰代码，
已经覆盖了绝大多数自定义需求。若确实需要复杂交互页面，
可以直接在 `content/` 下放 `.html` 文件——构建时会原样输出并照常参与 SEO 检测。

## Google Search Console 全自动化

配置一次，之后每次发布自动完成：**验证所有权 → 添加站点 → 提交 sitemap → 回读确认**。

### 一次性准备

1. 打开 [Google Cloud Console](https://console.cloud.google.com/)，创建项目
2. 启用两个 API：
   - **Google Search Console API**
   - **Site Verification API**
3. 创建服务账号，生成 JSON 密钥并下载
4. 在 GitHub 仓库 Settings → Secrets and variables → Actions → New repository secret
   添加 `GSC_SERVICE_ACCOUNT`，值为 JSON 密钥全文

### 之后全自动

| 阶段 | 动作 |
| --- | --- |
| 构建时 | 取验证令牌，把 `google-xxx.html` 写进站点产物 |
| 部署后 | 请求 Google 校验令牌 → 验证通过 |
| 验证后 | 站点加入 Search Console |
| 最后 | 提交 sitemap 并回读状态确认 |

**首次发布时验证会失败一次**——因为验证文件此时才刚部署上去，
Google 还抓不到。第二次发布即可通过，之后每次发布自动重新提交 sitemap。
这属于预期行为，日志会如实说明，不会让发布流程失败。

### 确认是否生效

发布完成后查看 Actions 运行摘要，会看到：

```
✅ 生成验证文件：https://你的域名/google-xxx.html
✅ 验证所有权：已验证
✅ 添加站点：https://你的域名/
✅ 提交 sitemap：https://你的域名/sitemap.xml
✅ 确认 sitemap 状态：已收录 · 错误 0 · 警告 0 · 最近抓取 2026-08-06
```

最后一行的「最近抓取」证明 Google 真的读取了 sitemap。

## IndexNow（Bing / Yandex / Seznam / Naver）

1. 生成一个 8–128 位随机字符串作为 Key
2. 仓库 Settings → Variables → Actions 添加 `INDEXNOW_KEY`
3. 在 `content/` 下创建 `<key>.txt`，内容为 Key 本身

**Google 不支持 IndexNow 协议**，Google 侧只能走上面的 Search Console 路径。

## 预期时间

| 搜索引擎 | 通常收录时间 |
| --- | --- |
| Bing / Yandex（有 IndexNow） | 数小时至一天 |
| Google（新站） | 数天至数周 |
| Google（已有权重的站点） | 更快 |

Google 官方说明：抓取需要「a few days to a few weeks」，
且「does not guarantee that inclusion will happen instantly or even at all」。
**没有任何工具能强制 Google 收录**，本项目能做的是确保技术层面不拖后腿。
